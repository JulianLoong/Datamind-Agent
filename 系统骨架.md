## 1. 模块拆分

| # | 模块 | 职责一句话 |
|---|------|-----------|
| M1 | **agent_engine** | 任务规划 + 交互式执行引擎，工具调用的主循环 |
| M2 | **tools** | 工具注册、封装、调用路由（ToolBench / 自建工具） |
| M3 | **recovery** | 失败恢复流水线：error_context 构建 → 候选生成 → PM 打分 → 选择执行 |
| M4 | **pref_model** | Preference Model 封装：加载、推理、训练、版本管理 |
| M5 | **trajectory** | 轨迹采集、存储（SQLite）、查询 |
| M6 | **pref_data** | 偏好对构造：从轨迹提取 (chosen, rejected)，质量检查 |
| M7 | **error_inject** | 错误注入器（可控测试用） |
| M8 | **eval** | 评估框架：指标计算、baseline 对接、消融实验编排 |
| M9 | **config** | 全局配置、LLM API key 管理、路径管理 |
| M10 | **api** | （可选）暴露 REST/CLI 入口，供人工触发任务或查看状态 |

## 3. 各模块职责与边界

### M1 agent_engine

**职责**：agent 的"大脑"。接收一个 Task，规划为步骤列表，逐步执行工具调用，检测失败，触发恢复。

**核心状态机**（`executor.py`）：
```
PLANNING → STEP_EXEC → SUCCESS → NEXT_STEP → ... → TASK_DONE
                        ↓
                      FAILED → RECOVERING → (选候选) → STEP_EXEC (重试当前步)
                                          → GIVE_UP → TASK_FAILED
```

**边界**：
- 不关心恢复"怎么选"——调用 `recovery.pipeline` 拿回一个 action 就执行
- 不直接操作数据库——通过 `trajectory.collector` 的回调接口写入

### M2 tools

**职责**：工具注册、参数校验、调用执行、结果标准化。

**边界**：
- 所有工具实现 `BaseTool` 接口
- `error_inject` 作为中间件包在 `ToolRegistry.execute()` 外层，对 agent 透明
- **不稳定边界**：ToolBench 适配层——依赖 ToolBench 的 API 稳定性，备选方案用 `builtin/simple_tools.py`

### M3 recovery

**职责**：agent 失败后的恢复决策。是 RPL 的核心流程。

**流水线**（`pipeline.py`）：
1. `context_builder.build(step, history, task_goal)` → `ErrorContext`
2. `candidate_gen.generate(error_context, k=K)` → `list[Candidate]`
3. `dedup.deduplicate(candidates)` → `list[Candidate]`
4. `selector.select(error_context, candidates)` → `Candidate`（冷启动时随机/首个，有 PM 时打分排序）
5. 返回选中的 action 给 executor

**边界**：
- recovery 模块是**无状态**的——不保存轨迹，不管理训练
- `selector` 通过依赖注入接收 `PrefModel`（可能为 None）

### M4 pref_model

**职责**：Preference Model 的生命周期管理。

**边界**：
- 推理（`model.py`）和训练（`trainer.py`）解耦——推理在 agent 运行时进行，训练是离线的
- 训练脚本 `scripts/train_pm.py` 负责读数据 → 训练 → 写 checkpoint
- 版本管理确保训练期间推理不受影响（新模型训练完才切换）
- **不稳定边界**：DPO 训练超参（β, lr, epochs）需要实验确定，首次用默认值

### M5 trajectory

**职责**：记录一切。是所有"学习"的数据源头。

**`collector.py`**：事件驱动，挂在 executor 上：
```python
executor.on_step_start(collector.on_step_start)
executor.on_tool_call(collector.on_tool_call)
executor.on_step_end(collector.on_step_end)
executor.on_recovery(collector.on_recovery)
```

**`store.py`**：SQLite 存储，核心表：
- `tasks`：task_id, goal, status, created_at
- `steps`：step_id, task_id, index, tool_name, params, result, success, tokens_used, latency_ms
- `recovery_attempts`：attempt_id, step_id, candidates_json, chosen_idx, outcome, pm_score

**边界**：
- 只存不改（append-only），不做任何分析逻辑
- 查询接口供 `pref_data` 和 `eval` 使用

### M6 pref_data

**职责**：从轨迹中提取偏好对，供 PM 训练。

**三种策略串联**：
1. `extractor` → 从同一 error_context 的多次恢复中提取 (chosen, rejected)
2. `heuristic` → 对无法提取的 case 用规则标注弱监督信号
3. `llm_judge` → 兜底：用强 LLM 做裁判

**`quality.py`**：后处理流水线（去重 → 去噪 → 置信度过滤 → 拆分 train/val）

**边界**：
- 只产出 `data/pref_pairs/*.jsonl`，不触发训练
- **不稳定边界**：策略 B 的启发式规则数量和内容需要迭代；策略 C 的 LLM prompt 需要调优

### M7 error_inject

**职责**：在工具调用层注入可控错误，用于产生训练数据和测试。

**注入类型**：
- `timeout`：让工具调用超时
- `param_error`：篡改参数
- `empty_result`：返回空值
- `wrong_result`：返回格式不符预期的结果

**配置**：概率注入（如 20% 概率）或指定步骤注入

**边界**：
- 仅用于测试/训练数据积累，正式评估时可关闭
- 通过装饰器模式包在 `ToolRegistry` 上，对 agent 和 recovery 完全透明

### M8 eval

**职责**：实验编排和指标计算。

**边界**：
- 依赖 `trajectory` 的数据产出指标，不自己跑 agent（`runner.py` 调用 agent_engine）
- baseline 实现在 `baselines.py`，各自是 `RecoverySelector` 的不同实现

### M9 config

**职责**：集中管理所有可调参数。

### M10 api

**职责**：（可选）如果需要 Web UI 或远程调用，加一层薄 wrapper。**当前不做**。

## 4. 核心接口

```python
# ========== tools/base.py ==========

@dataclass
class ToolResult:
    success: bool
    data: Any
    error_type: str | None = None   # "timeout" | "param_error" | "empty_result" | ...
    error_message: str | None = None
    tokens_used: int = 0
    latency_ms: float = 0.0

class BaseTool(ABC):
    @abstractmethod
    def name(self) -> str: ...

    @abstractmethod
    def description(self) -> str: ...

    @abstractmethod
    def schema(self) -> dict[str, Any]: ...  # JSON Schema for params

    @abstractmethod
    def execute(self, **params) -> ToolResult: ...

# ========== tools/registry.py ==========

class ToolRegistry:
    def register(self, tool: BaseTool) -> None: ...
    def execute(self, tool_name: str, params: dict) -> ToolResult: ...
    def list_tools(self) -> list[BaseTool]: ...

# ========== agent_engine/step.py ==========

class StepStatus(Enum):
    PENDING = "pending"
    RUNNING = "running"
    SUCCESS = "success"
    FAILED = "failed"
    RECOVERING = "recovering"
    SKIPPED = "skipped"

@dataclass
class Step:
    index: int
    description: str
    tool_name: str | None = None
    params: dict | None = None
    status: StepStatus = StepStatus.PENDING
    result: ToolResult | None = None
    recovery_attempts: list["RecoveryAttempt"] = field(default_factory=list)

@dataclass
class RecoveryAttempt:
    candidates: list["Candidate"]
    chosen_index: int
    outcome: StepStatus           # 最终成功还是失败
    pm_scores: list[float] | None = None

# ========== agent_engine/planner.py ==========

class Planner:
    def plan(self, task_goal: str, available_tools: list[BaseTool]) -> list[Step]: ...

# ========== agent_engine/executor.py ==========

class Executor:
    """核心执行引擎。通过回调与 trajectory/recovery 解耦。"""

    def __init__(self, registry: ToolRegistry, planner: Planner,
                 recovery_pipeline: "RecoveryPipeline",
                 collector: "TrajectoryCollector"):
        ...

    async def run_task(self, task_goal: str, max_steps: int = 20,
                       max_retries_per_step: int = 3) -> "TaskResult": ...

@dataclass
class TaskResult:
    task_id: str
    goal: str
    status: str                   # "success" | "failed"
    steps: list[Step]
    total_tokens: int
    total_latency_ms: float

# ========== recovery/ ==========

@dataclass
class ErrorContext:
    task_goal: str
    step_description: str
    tool_name: str
    tool_params: dict
    error_type: str
    error_message: str
    recent_history: list[dict]    # [{tool, success, brief_result}, ...]

    def to_prompt(self) -> str: ...   # 渲染为自然语言模板

@dataclass
class Candidate:
    reasoning: str                # 错误分析
    action: str                   # 恢复动作描述
    tool_name: str | None         # 要调用的工具（可能不变）
    tool_params: dict | None      # 新参数
    raw_text: str                 # LLM 原始输出（用于 PM 输入）

class ErrorContextBuilder:
    def build(self, step: Step, history: list[Step], task_goal: str) -> ErrorContext: ...

class CandidateGenerator:
    async def generate(self, ctx: ErrorContext, k: int = 3) -> list[Candidate]: ...

class CandidateDedup:
    def deduplicate(self, candidates: list[Candidate]) -> list[Candidate]: ...

class RecoverySelector(ABC):
    @abstractmethod
    async def select(self, ctx: ErrorContext, candidates: list[Candidate]) -> Candidate: ...

class DefaultSelector(RecoverySelector):
    """冷启动：选第一个或随机"""
    def __init__(self, strategy: str = "first"): ...  # "first" | "random"

class PMSelector(RecoverySelector):
    """使用 Preference Model 打分排序"""
    def __init__(self, pref_model: "PrefModel"): ...

class RecoveryPipeline:
    def __init__(self, context_builder, candidate_gen, dedup, selector):
        ...
    async def recover(self, step, history, task_goal) -> RecoveryAttempt: ...

# ========== pref_model/ ==========

class PrefModel:
    def __init__(self, model_path: str | None = None, device: str = "cuda"): ...

    def score(self, error_context: ErrorContext, candidate: Candidate) -> float: ...

    def rank(self, error_context: ErrorContext, candidates: list[Candidate]) -> list[tuple[int, float]]: ...

    def is_loaded(self) -> bool: ...

class DPOTrainer:
    def __init__(self, config: "TrainingConfig"): ...
    def train(self, train_path: str, val_path: str) -> str: ...  # 返回 checkpoint 路径
    def load_checkpoint(self, path: str) -> PrefModel: ...

# ========== trajectory/ ==========

class TrajectoryCollector:
    def on_step_start(self, step: Step): ...
    def on_tool_call(self, step: Step, tool_name: str, params: dict, result: ToolResult): ...
    def on_step_end(self, step: Step): ...
    def on_recovery(self, step: Step, attempt: RecoveryAttempt): ...

class TrajectoryStore:
    def save_task(self, result: TaskResult) -> None: ...
    def get_trajectory(self, task_id: str) -> TaskResult: ...
    def query_failures(self, error_type: str | None = None,
                       limit: int = 100) -> list[dict]: ...
    def query_recovery_attempts(self, task_id: str) -> list[RecoveryAttempt]: ...

# ========== pref_data/ ==========

@dataclass
class PreferencePair:
    error_context: ErrorContext
    chosen: Candidate               # 更好的恢复方案
    rejected: Candidate             # 更差的恢复方案
    source: str                     # "outcome" | "heuristic" | "llm_judge"
    confidence: float               # 0.0 ~ 1.0

class PreferenceExtractor:
    def extract(self, store: TrajectoryStore) -> list[PreferencePair]: ...

class HeuristicAnnotator:
    def annotate(self, error_ctx: ErrorContext, candidates: list[Candidate]) -> list[PreferencePair]: ...

class LLMJudge:
    async def judge(self, error_ctx: ErrorContext,
                    cand_a: Candidate, cand_b: Candidate) -> tuple[int, float]: ...
    # 返回 (winner_index, confidence)

class DataQualityFilter:
    def filter(self, pairs: list[PreferencePair], min_confidence: float = 0.6) -> list[PreferencePair]: ...
    def deduplicate(self, pairs: list[PreferencePair]) -> list[PreferencePair]: ...

# ========== eval/ ==========

class MetricsCalculator:
    def compute(self, results: list[TaskResult]) -> dict[str, float]: ...

class EvalRunner:
    def run(self, config: "EvalConfig") -> dict[str, dict[str, float]]: ...
```

## 5. 关键数据结构（已内嵌在接口中，汇总）

```
TaskResult
  ├── task_id, goal, status, total_tokens, total_latency_ms
  └── steps: list[Step]
        ├── index, description, tool_name, params, status
        ├── result: ToolResult
        │     ├── success, data, error_type, error_message
        │     └── tokens_used, latency_ms
        └── recovery_attempts: list[RecoveryAttempt]
              ├── candidates: list[Candidate]
              │     ├── reasoning, action, tool_name, tool_params, raw_text
              ├── chosen_index, outcome
              └── pm_scores: list[float] | None

PreferencePair
  ├── error_context: ErrorContext
  │     ├── task_goal, step_description, tool_name, tool_params
  │     ├── error_type, error_message
  │     ├── recent_history: list[dict]
  │     └── to_prompt() → str
  ├── chosen: Candidate
  ├── rejected: Candidate
  ├── source: "outcome" | "heuristic" | "llm_judge"
  └── confidence: float
```

SQLite 表结构（`trajectory/store.py`）：

```sql
CREATE TABLE tasks (
    id TEXT PRIMARY KEY,
    goal TEXT NOT NULL,
    status TEXT NOT NULL,
    total_tokens INTEGER DEFAULT 0,
    total_latency_ms REAL DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE steps (
    id TEXT PRIMARY KEY,
    task_id TEXT REFERENCES tasks(id),
    step_index INTEGER NOT NULL,
    description TEXT,
    tool_name TEXT,
    params_json TEXT,
    status TEXT NOT NULL,
    result_json TEXT,
    tokens_used INTEGER DEFAULT 0,
    latency_ms REAL DEFAULT 0
);

CREATE TABLE recovery_attempts (
    id TEXT PRIMARY KEY,
    step_id TEXT REFERENCES steps(id),
    candidates_json TEXT NOT NULL,    -- list[Candidate] 序列化
    chosen_index INTEGER NOT NULL,
    outcome TEXT NOT NULL,
    pm_scores_json TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 6. 主链路时序

### 6.1 任务执行主链路

```
User/Script                Executor                Planner          ToolRegistry       RecoveryPipeline
    │                         │                       │                    │                    │
    │  run_task(goal)         │                       │                    │                    │
    │────────────────────────>│                       │                    │                    │
    │                         │  plan(goal, tools)    │                    │                    │
    │                         │──────────────────────>│                    │                    │
    │                         │  [Step1, Step2, ...]  │                    │                    │
    │                         │<──────────────────────│                    │                    │
    │                         │                       │                    │                    │
    │                         │  for step in steps:   │                    │                    │
    │                         │  ────────────────────>│                    │                    │
    │                         │                       │                    │                    │
    │                         │  execute(tool, params)│                    │                    │
    │                         │────────────────────────────────────────────>│                    │
    │                         │                       │                    │                    │
    │                         │  ToolResult           │                    │                    │
    │                         │<────────────────────────────────────────────│                    │
    │                         │                       │                    │                    │
    │                   [success?]                    │                    │                    │
    │                    yes ↓ no                     │                    │                    │
    │                   next step │                    │                    │                    │
    │                         │   recover(step, hist, goal)               │                    │
    │                         │─────────────────────────────────────────────────────────────────>│
    │                         │                       │                    │  RecoveryAttempt    │
    │                         │<─────────────────────────────────────────────────────────────────│
    │                         │   execute(chosen_action)                   │                    │
    │                         │────────────────────────────────────────────>│                    │
    │                         │                       │                    │                    │
    │                         │  ... (最多 max_retries 次)                 │                    │
    │                         │                       │                    │                    │
    │  TaskResult             │                       │                    │                    │
    │<────────────────────────│                       │                    │                    │
```

### 6.2 恢复流水线内部时序

```
RecoveryPipeline          ContextBuilder      CandidateGen(LLM)      Dedup      Selector
      │                         │                      │               │             │
      │  build(step,hist,goal)  │                      │               │             │
      │────────────────────────>│                      │               │             │
      │  ErrorContext           │                      │               │             │
      │<────────────────────────│                      │               │             │
      │                         │                      │               │             │
      │  generate(ctx, k=3)     │                      │               │             │
      │────────────────────────────────────────────────>│               │             │
      │  [Cand1, Cand2, Cand3]  │                      │               │             │
      │<────────────────────────────────────────────────│               │             │
      │                         │                      │               │             │
```

## 7. 权限、隔离和边界

### 7.1 模块间依赖方向（单向，禁止反向）

```
agent_engine → tools, recovery, trajectory(collector)
recovery    → pref_model(可选), agent_engine(无)   ← recovery 不依赖 executor
pref_data   → trajectory(store)                    ← 只读轨迹
pref_model  → (无内部依赖)                          ← 独立模块
eval        → agent_engine, trajectory, recovery
error_inject→ tools(装饰器)                         ← 横切，但不侵入
config      → (被所有模块依赖)
```

### 7.2 隔离策略

| 维度 | 策略 |
|------|------|
| **推理 vs 训练** | `PrefModel` 推理在 agent 运行时；`DPOTrainer` 训练是离线脚本。两者通过 checkpoint 文件交接，不在同一进程 |
| **数据流** | 轨迹库是 append-only；偏好对是只增不改的文件；PM 版本通过目录隔离（`pm_checkpoints/v1/`, `v2/`） |
| **LLM API vs 本地模型** | agent LLM（GPT-4o/Claude）走 API；PM（Qwen2.5）走本地 GPU。配置中分别管理 |
| **错误注入** | 通过装饰器包在 `ToolRegistry` 上，一个 config flag 即可全局开关，不改动任何业务代码 |

### 7.3 明确标注的不稳定边界

| 边界 | 不稳定原因 | 当前假设 | 需要验证的时机 |
|------|-----------|---------|--------------|
| ToolBench 适配 | 外部依赖，API 可能变化 | 用 ToolBench 的 REST API | M1 搭建时验证 |
| K 值（候选数量） | 影响质量 vs 成本权衡 | K=3 | M2 完成后消融 |
| DPO 超参 β, lr, epochs | 直接影响训练效果 | β=0.1, lr=5e-5, epochs=3 | M4 首次训练时 |
| 候选去重算法 | 语义相似度判断不精确 | 基于文本 embedding 余弦相似度 + 阈值 | M2 实现时迭代 |
| 偏好对最小数据量 | "500 条够不够"是猜想 | 500 条 | M3 数据积累后 |
| 策略 B 启发式规则 | 规则数量和内容需要迭代 | 5-8 条 | M3 数据积累后 |
| 恢复动作的执行方式 | "PM 选出一个 candidate 后怎么执行" | 直接用 candidate 的 tool_name + params 调用 | M2 实现时明确 |
| `Candidate.tool_params` 结构 | 可能与 `BaseTool.schema()` 不兼容 | 假设 LLM 生成的 JSON 可直接传给工具 | M2 集成时验证 |

---

以上骨架覆盖了实施方案中的所有核心模块，接口签名和数据结构足够直接开始编码。建议编码顺序：`config` → `tools/base` → `tools/registry` → `trajectory/store` → `agent_engine` → `error_inject` → `recovery` → `pref_model` → `pref_data` → `eval`。
